What you'll build

Your solution must include.

Five elements. The first four are required; the custom tool is optional but encouraged.

  1. Skills Required

    • Define any relevant additional context required to address your use case.
    • Configure the When to use conditions (keywords, phrases, or a tool) that trigger the skill.

  2. Specialized Agents Required · 2 or more

    • Identify and create 2 or more specific sub-tasks within your overall solution that can be solved with a specialized agent.
    • Implement the specialized agents in Mark.
    • Clearly define each agent's purpose, the input parameters it requires, and the output it produces.

  3. Out-of-the-box tools Required

    • Use existing tools within your agents and workflows, such as search_web, browse_web, send_email, create_canvas, write_content_to_file or generate_or_edit_image.
    • You can also use custom tools (see below) to achieve the desired outcome.

  4. Workflow agent Required

    Implement a workflow agent that orchestrates multiple steps across your specialized agents and/or other available agents. It must include:

    • A trigger that starts the workflow.
    • At least two specialized agents arranged into a complete process.
    • At least one piece of workflow logic, such as a condition (branching), a loop, or a code step, where it fits your use case.

  5. Custom tool Optional but encouraged

    Design and implement a custom tool that enhances or supports the solution you are building.

    • Identify a need. Find a function not adequately covered by existing out-of-the-box tools, where a custom tool would significantly improve effectiveness or efficiency. Examples: a tool that calls a specific external public API, a specialized data transformation function, or a unique content formatting utility.
    • Design it. Define the tool's purpose, its input parameters (with types and descriptions), and its expected output. Consider how it will fit into your existing workflow.
    • Implement it. Build the tool and run it locally or online (see the appendix for ngrok and Vercel). Integrate it into your agent's workflow, demonstrating how your agent calls it and uses its output.

Appendix · Technical challenge

Set up and host your custom tool.

Covers local development for rapid iteration and deployment for production or demo environments. Provided as guidance.

Local development & testing with ngrok

Expose your local server to test your custom tool with your Mark instance. This allows rapid iteration and debugging during development.

Set up ngrok

  1. Install ngrok. Download and install it from ngrok.com/download.
  2. Create an ngrok account and authenticate.
    ngrok config add-authtoken YOUR_AUTH_TOKEN
  3. Start the tunnel. In a separate terminal, expose your local server (default port is 8000):
    ngrok http 8000
  4. Use the ngrok URL. Copy the https:// forwarding URL from the ngrok output (for example https://abc123.ngrok.io). You will use it to register your tool with Mark.

Register your tool with Mark

Once your app is running locally and exposed through ngrok:

  1. Go to Connectors > Tool Registry in Mark, then open the Tools Registry page.
  2. Click Add Tool Registry.
  3. Configure it:
    • Registry URL: your ngrok HTTPS URL followed by /discovery.
    • Name: a descriptive name, such as "Custom Tool - Local Dev".
    • Description: optional, a brief description of your tools.
    • Authentication: configure if your tools need it (for example Opti ID).
  4. Save and verify. Click Save. Mark will attempt to discover tools from your endpoint. Verify that your custom tools appear in the registry.

Test your registered tool

  • Verify tool discovery: make sure your tools are listed correctly in the Tools Registry.
  • Invoke and test: go to Mark Chat or Workflows and invoke your tool (for example, by typing a command that triggers it). Verify that results come back correctly.

Production / demo hosting with Vercel

Deploy your custom tool for production or demo environments, using Vercel's serverless capabilities for scalability, ease of deployment and automatic SSL.

Prepare your tool's codebase

  • Structure for serverless functions. Vercel automatically detects serverless functions in an api directory at the root of your project. Each file in api becomes a serverless function.
    • Node.js: api/tools/my-custom-tool.js and api/discovery.js
    • Python: api/tools/my-custom-tool.py and api/discovery.py
  • Implement the discovery endpoint. /discovery must be a serverless function that returns the metadata for all your tools.
  • Implement tool endpoints. Each tool (for example /tools/my-custom-tool) is its own serverless function that handles the logic for that tool.
  • Manage dependencies. Include a package.json (Node.js) or requirements.txt (Python) in your project root. Vercel installs them during deployment.

Set up and deploy to Vercel

  1. Create a Vercel account. Sign up for a free account if you don't have one.
  2. Install the Vercel CLI (optional but recommended): npm install -g vercel (Node.js) or pip install vercel (Python).
  3. Link to a Git repository. Push your tool's code to GitHub, GitLab or Bitbucket.
  4. Deploy your project.
    • Git integration (recommended): in your Vercel dashboard, click New Project and select your repository. Vercel detects your framework and deploys, assigning a URL such as your-project-name.vercel.app.
    • Vercel CLI: in your project directory, run vercel and follow the prompts.
  5. Configure environment variables (if applicable). Store API keys, database credentials or other secrets in your Vercel project settings under Environment Variables. They are injected into your functions at runtime.

Register your tool with Mark

Once your tool is deployed and you have its public URL (for example https://your-tool-name.vercel.app):

  1. Go to Connectors > Tools Registry in Mark.
  2. Click Add Tool Registry.
  3. Configure it:
    • Registry URL: your Vercel URL followed by /discovery (for example https://your-tool-name.vercel.app/discovery).
    • Name: a descriptive name, such as "Custom Tool - Production".
    • Authentication: configure if your tools need it (for example Opti ID).
  4. Save and verify. Mark will attempt to discover your tools from the Vercel-hosted /discovery endpoint.

API endpoints

The tools SDK (@optimizely-opal/opal-tools-sdk) automatically generates an endpoint for each tool and a discovery endpoint.

Discovery endpoint: /discovery

Returns metadata about all available tools, including their names, descriptions, parameters, endpoints, HTTP methods and authentication requirements. Example response:

{
  "functions": [
    {
      "name": "get_cmp_root_folders",
      "description": "Fetches root-level folders from CMP library",
      "parameters": [],
      "endpoint": "/tools/get-cmp-root-folders",
      "http_method": "POST",
      "auth_requirements": [
        {
          "provider": "OptiID",
          "scope_bundle": "default",
          "required": true
        }
      ]
    }
    // ...other functions
  ]
}

Tool endpoints: /tools/{tool-name}

Each tool is exposed as a separate HTTP endpoint. For example:

POST /tools/get-cmp-root-folders
